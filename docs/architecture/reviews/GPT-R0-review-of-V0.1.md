[R011] [08-sim-core.md#§2 D6/D8、§3；06-data-formats.md#§7；14-interfaces.md#§2] [严重度: 阻断] [类型: 缺口]
问题：标准 PCG32 XSH-RR 的内部 state 和 stream increment 都是 64 位（来源 [E1]）；32 位 Math.imul 可以通过拆分高低字实现，但单一 uint32 状态不等同标准 PCG32。原文未规定精确变体、64 位进位、seed/stream 派生、随机取样、整数范围和保存状态。D8 允许 xxHash32/64，14 却要求 16 位十六进制；两种哈希并非同一输出。
建议：确定一种 PRNG：保留标准 PCG32，双 uint32 表示每个 64 位状态和 increment，固定已知输出向量；或选定简单 32 位 PRNG 并更名、固定向量（低迁移代价，随机流改变须升 simVersion）。冻结 seed 派生、系统编号、每回合重播或连续流策略、随机消费顺序。哈希统一为 xxHash64（或其他明确 64 位算法），固定 seed、字节序和 16 个小写十六进制字符，加入 golden vectors。

[R033] [07-rendering.md#§6、§8、§11；13-visual-ui.md#§1.3、§3] [严重度: 重要] [类型: 可行性]
问题：MSDF 2048²/32²=4096 是零 padding 理论字数；若每边需4px 留白，40×40 单元则最多 51²=2601 字/页，字体双套和 mipmap 还要增加空间。5000 个字×32²≈5.12M 像素正确，但不等于 KTX2 实际压缩 5 MB，GPU 解码后与图集空隙另算。每帧纹理局部更新也受 Three.js 锁定版本 API 影响（未核实）；解析拾取若不考虑 LOD0 噪声、geomorph 或高低档插值，在格边和山峰不可能保证所有点100%一致。
